# PROJECT_STATE.md — Crockid Price Tracker

## 🎯 Идея проекта

Учебный проект для портфолио начинающего аналитика данных: **анализ цен на продукцию бренда Crockid на Wildberries**.

**Бизнес-вопрос:** как устроено ценообразование Crockid на WB? Есть ли разница цен по размерам, насколько честны скидки, как меняется цена во времени?

**Текущий фокус:** анализ влияния размеров на цену (на данных `sizes_json`).

## 🛠 Стек

- Python 3.13, pandas, sqlite3, matplotlib, seaborn, json
- `wb-private-api-python` (с `[browser]`, требует Chrome + Rosetta 2 на macOS)
- SQLite (`data/prices.db`), таблица `prices`
- cron (macOS, `crontab -e` через `nano`), скрипт `run_parser.sh`
- VS Code + расширения: Python, Jupyter, SQLite (alexcvzz), Rainbow CSV
- Git + GitHub Desktop

## ✅ Что уже сделано

1. **Парсер WB работает** (`src/parse_wb_test.py`):
   - Ищет «Crockid», собирает ~2000+ товаров.
   - Очистка: фильтр по бренду, удаление дублей и пустых артикулов.
   - Сохраняет в `data/wb_clean.csv` и в SQLite.
   - Собирает `price` (мин. product), `basic_price` (мин. basic), `sizes_json`, `sizes_count`, `supplier`, `rating`, `feedbacks`, `url`.

2. **Схема SQLite** (таблица `prices`, 14 колонок):
   `id, timestamp, marketplace, article, name, brand, price, basic_price, sizes_json, sizes_count, supplier, rating, feedbacks, url`

3. **Cron настроен:** `run_parser.sh` запускается ежедневно в 12:00 (macOS, `nano` как редактор).

4. **Анализ размеров:** данные собираются корректно. Пример:
`1708452295 | 843.0 | 1179.0 | 3 | [{"size":"42-44","product":843.0,"basic":1179.0}, ...]`

Первые товары имеют **одинаковую цену по всем размерам** — это первый инсайт.

## ⚠️ Важные нюансы (не забыть!)

- **`.gitignore`:** `data/`, `*.db`, `*.csv`, `.venv/`, `logs/`, `downloaded_files/`, `__pycache__/`, `.vscode/`.
- **Chrome + Rosetta 2** нужны для `wb-private-api-python` на macOS (Apple Silicon). Ошибка `Chrome not found` → установить Chrome, перезапустить VS Code. Ошибка `Missing a macOS dependency: Rosetta 2` → `softwareupdate --install-rosetta`.
- **cron на macOS:** если ноутбук спит в 12:00 — задача не выполнится. Для учебного проекта это нормально.
- **Данные «плавают»** от запуска к запуску (WB отдаёт разное количество: 2435, 2139, 2132). Это нормально, поэтому SQLite копит историю, а не CSV.
- **Размеры:** у одного артикула может быть 1–15 размеров. Стратегия: `price` = мин. `product`, `basic_price` = мин. `basic`, полная детализация в `sizes_json`.
- **`downloaded_files/`** — создаётся библиотекой WB, добавить в `.gitignore`, не удалять во время работы.

## 📜 История решений (чтобы не повторяться)

- A/B-тест — **отклонён** в пользу ценового анализа.
- Ozon — **полностью убран** из проекта (антибот, ручная выгрузка, MCP-сервер не подошёл). Проект только по Wildberries.
- Airflow — **отклонён** в пользу локального cron (проще для студента).
- Данные на GitHub — **не храним** (лимиты, раздувание репозитория). Бэкап — CSV на Яндекс Диске (опционально).
- VS Code — **выбран** (Jupyter + SQLite + Python в одном окне).
